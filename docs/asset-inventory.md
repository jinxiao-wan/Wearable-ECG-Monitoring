# Project asset inventory

| Workstream | Included evidence or implementation | Native/source items missing from uploads |
| --- | --- | --- |
| System hardware | Component description and original circuit schematic | Firmware, full BOM and verified module documentation |
| Electrodes and materials | Original concept diagram and design text | Electrode fabrication drawings, material test records |
| SolidWorks / mechanical | CAD renders, printed-part photos, wearable prototype photos | SLDPRT, SLDASM, SLDDRW, STEP, STL and dimensioned drawings |
| PCB | Schematic image, layout image, manufactured-board photographs | SchDoc, PcbDoc, PrjPcb, Gerber/drill exports, libraries, DRC report |
| WeChat software | Original first-party code and rebuilt runnable app | Original cloud backend and server deployment |
| Signal processing | MATLAB source, repaired MATLAB functions, Python pipeline, MIT-BIH record and annotation evaluation | Physical sensor calibration and independent hardware recordings |
| Team process | Laboratory, prototyping, discussion and meeting photos | Detailed dated engineering log or verified manufacturing revision history |
| Project outputs | Public summaries of completion materials and utility-model grant notice | Current legal-status verification, paper publication evidence |

Images are stored once in `demo/assets/` and used by both the GitHub documentation and website. [Visual source manifest](visual-sources.json) lists original archive locations, source hashes and web-preparation steps. [Original-code manifest](source-manifest.json) records the preserved software and public sample data.

No stock or generated photographs are presented as project evidence. The literature images and commercial-product images in the source slides are excluded from the project gallery to avoid confusing related work with the team's own hardware.
